# Stage 0 interface and recovery decisions

These are candidate implementation decisions for the recorded v1 scope. The requirement records define observable behavior. The interfaces below identify owners, failure handling, and the test seams needed to implement it.

## Desktop and audio

See the [C4 workspace](../architecture/workspace.dsl), [CQRS application interfaces](../architecture/cqrs.md), and [LiteDB repository design](../architecture/persistence.md) for component owners, request and handler signatures, and write transaction boundaries.

- The internal dispatcher accepts a typed request and dispatches to one registered handler. A request context carries correlation ID and cancellation; the result distinguishes success, validation, conflict, cancellation, and dependency failure. Queries read immutable projections. Serialize mutations by the state they modify. No library job may block a navigation handler.
- Route UI changes through an async adapter bound to `Dispatcher.UIThread`. A presentation delta carries its view or session key plus sequence. Ignore stale deltas after a newer update or when the owning view is closed. Keep dialog ownership at the window shell so changing presentation does not move draft or keyboard focus.
- The playback strategy exposes capabilities, transport, a current state snapshot, and optional bounded visualization telemetry. The app owns the queue. SoundFlow owns the audio graph. Stop the old backend before activating a new one, leave the selected track intact, and await Play.
- The native visualization source reads the newest complete 1,024-sample mixed output window. A frame carries the capture sequence, monotonic timestamp, sample rate, 64 signed waveform points, and 32 logarithmic frequency-band levels. The source suppresses duplicate frames and windows at least 500 ms old. It does not open an audio device for telemetry.
- Use a linear deck fade with endpoint gains A=1, B=0 and A=0, B=1. At midpoint use equal gains of 0.5. Persist the selected automatic fade duration as a local override or an eligible shared default. Clamp a fade to actual remaining time and defer the fade until the incoming deck is ready. Seeking and explicit skipping abandon any pending automatic fade and recompute from the new active track. Pause freezes the active fade. Manual crossfader movement cancels automatic gain changes and takes over from the current position. Preserve the outgoing track if preparing the incoming deck fails. Treat the ten-band master equalizer as a candidate for Stage 0 review.

## Local configuration and settings

- `appsettings.json` is local bootstrap input. Expand only the built-in absolute path variables for first-run defaults. Preserve unknown keys and a valid existing configuration. Apply the selected path and log filters at restart. Never use the process working directory to resolve a persistent location.
- Diagnostics opens the active rolling-log directory through the OS file manager. It can create a missing directory when rolling logging is enabled. When rolling logging is disabled, it opens the configured directory if it already exists.
- An active library Operator can save a relative beets naming template, supported import behavior, and a selection of the native plugins approved in host launch settings. The registered host provisions catalog, music, and YAML paths in its launch settings. It verifies selected plugins before committing the typed configuration and operation receipt at the expected revision. Subsequent native jobs generate private YAML from the committed profile.
- Ordinary preferences are defined by a typed registry with scope, validation, schema version, and default. Cache eligible shared values with their host revision. A local action may remove a local override; it cannot change the shared value unless it submits a separately authorized host command.
- Appearance registers `appearance.theme` as shareable text. STB07 uses Follow system (`system`) and Dark (`dark`), with Follow system as the built-in fallback. Choosing a theme stages a preview at the displayed local revision. Apply commits the local value and continues to expose the cached shared value. Inherit clears the local override and resolves the current shared or built-in value.
- Contextual shortcut dispatch evaluates the active modal or view scope first. Expose the winning action in the editor and require conflict resolution before changing an existing binding. Global registrations are opt-in and carry only playback action IDs. Registration denial does not alter local bindings.
- `ResolveContextualShortcut` accepts the active contexts in view precedence order and checks the active dialog first. `AssignShortcut` rejects a collision within one scope. Each successful contextual edit saves only device-local overrides. `SetGlobalPlaybackShortcuts` uses a separate revision for the accepted registration and releases it when the desktop workspace closes.
- A system activation must match an accepted playback binding and its current registration revision before reaching the playback dispatcher. On Windows, the host requests thread-owned hotkeys and keeps the prior set if the operating system rejects a replacement. A Play or pause activation resolves against the playback session inside the transport command.
- On Linux, an explicit enable uses the XDG GlobalShortcuts portal when available. The desktop watches the request path before issuing each portal call and validates the returned session and shortcut IDs. Denial releases the candidate session. Portal remapping updates the observed trigger description and session closure clears the accepted bindings.
- Notifications register Sync completed as a shareable Boolean and Peer needs attention and Playback errors as local Boolean preferences. The built-in value is On for all three. A reset preview shows each explicit local override and its inherited value. Confirmation compares the local and cached shared category revisions in the same transaction as the clear.

## CLI and plugin messages

- CLI YAML declares a schema version, invocation mode, executable, argument tokens, action-to-request mapping, reply/status mapping, capabilities, and timeouts. One-shot commands own separate processes. A session strategy owns one worker and correlates newline-delimited JSON replies by request ID. Never execute YAML content as shell input. Unknown or missing capabilities disable the dependent controls.
- The version 1 local file stores `profileId`, `revision`, `schemaVersion`, `mode`, `executable`, `arguments`, `capabilities`, `timeoutMilliseconds`, `actions`, and `reply`. Each action names `action` and carries its own argument tokens in `oneShot` mode or a `requestKind` in `session` mode. A one-shot Play uses the whole token `{path}`. One-shot Seek uses `{positionMs}`. The reply maps `statusField` and `statusValues`, with optional position and duration fields measured in milliseconds. Transport requires Play, Pause, and Stop so the strategy can stop before switching. Seek requires its own action and a readable position field.
- A session request is one UTF-8 JSON line with a unique `id`, mapped `kind`, media `path`, and `positionMs`. Its reply echoes the `id` and contains the configured status and time fields. One-shot stdout contains one JSON object and the process must exit successfully. An optional `error` denotes a rejected action. The desktop rejects an oversized or malformed reply, reports timeout or process exit separately, and does not echo raw stdout, stderr, or arguments.
- Plugin packages declare a stable ID, version, contract range, entry point, and contributions. The host starts a locally trusted version and negotiates a protocol before showing contributions. IPC carries version, request/event kind, correlation, plugin identity, and a bounded payload. The plugin supplies declarative UI and invokes registered actions through CQRS. Ignore stale telemetry, have a timeout, and detach failed contributions. Worker processes share user permissions; transport validation and worker lifecycle provide crash containment.
- The local package is a ZIP with a root `plugin.json` containing `pluginId`, `version`, `minimumProtocol`, `maximumProtocol`, `entryPoint`, and `contributions`. Each declaration contains `contributionId` and `kind`. Use a lower-case package ID and a three-part version with an optional prerelease suffix. The entry point is a case-exact archive file. Package admission rejects ambiguous or unsafe paths. The local trust decision applies to the installed version and exact archive digest.
- The version 1 worker entry point is a .NET assembly with its hosting files in the package. The host sends one `hello` JSON line with `protocol`, `requestId`, `pluginId` and `version`. The worker replies `ready` with the same identifiers and a subset of the declared contribution IDs and kinds. A timeout, wrong identity or invalid declaration prevents activation.
- An `invoke` action adds `operationId`, `contributionId`, and bounded string `arguments` to the request. The paired `result` echoes the request identity and contribution and returns a short plain-text `message`. It may request a `hostAction` only when that exact action descriptor declares the grant. The v1 grant `playback.pause` targets the initiating desktop's active playback session. Timeout, cancellation during IPC, and malformed replies retire the channel.
- A `panel` declaration may specify `title`, `actionId`, and up to 16 ordered `fields`. Fields have a unique `id`, `label`, `kind`, `required`, and `maximumLength`. A `text` field has a length limit of 1–1024 characters. A read-only `currentTrack` field uses a limit of zero and, when present, binds the host's current track ID. The worker must offer both the panel and its declared action. The submit request accepts editable text only. The host verifies that the track and worker activation still match the opened panel before invoking the action. The linked action requires this panel context.
- A worker offers scoped visualization telemetry by declaring `telemetryProtocol: 1` on a manifest-declared visualization in its `ready` response. The desktop sends `visualize` with the standard request and plugin identity plus `contributionId`, `sessionId`, `sequence`, `sampleRate`, `waveform`, and `spectrum`. A `frame` reply echoes the request, contribution, session and sequence, with 1–64 finite `levels` from zero to one. A reply with an older sequence or expired source window is discarded. A malformed reply or a one-second response timeout retires the worker and detaches its selected visualization.

## Host and replication

- The private HTTPS API scopes registration, catalog snapshots and pages, library jobs, listening edits, shared preferences, notification pulls and acknowledgments, and media peer operations. Store credentials in the OS credential store. A command carries its origin instance, stable operation ID, and expected revision when overwriting prior state.
- A desktop registers its own pre-provisioned identity against the configured HTTPS host and the reviewed registry revision. Its credential selection is local. The roster carries the display name, identity, role, access state, and optional Last seen observation. The host coalesces authenticated activity for each active desktop to at most one write per minute. The registry revision advances on enrollment and revocation. A provisioned Operator can revoke another desktop at the reviewed revision. A Listener can originate ordinary host changes after enrollment. A revoked identity stays visible to active readers with its last retained observation and loses access to host operations.
- Persist host revisions monotonically per library, allocate stable IDs independently of disk paths, and publish tombstones for deletions. A snapshot fixes an inclusive upper revision before paging. Fetch subsequent changes after that upper revision. On a replica, persist received records and the contiguous cursor together. Acknowledge notifications only through that committed cursor. On expiry, rebuild only the synchronized projection and preserve local registrations, settings, drafts, and pending work.
- Before invoking beets, store intent and stable operation ID. After successful or interrupted execution, reconcile observed catalog and files against prior state. Publish revisions and delivery records together after reconciliation. A retry of uncertain external work must resolve what happened first. For listening history, distinct play IDs append and duplicate play IDs are idempotent. Conflicting playlist and favorite edits preserve a draft for explicit resolution.

## Media layout and Android navigation

- Each Android profile declares a player and template version, suggested root, relative path template, and optional relative playlist format. Validate relative ownership, reserved and colliding names, and expected source readability before publication. Keep staged bytes outside the active share until publication. Track uploaded files in a device-scoped manifest. Reconciliation may touch only paths owned by that manifest.
- Dropping a saved playlist in the Sync list stages a playlist file in the selected player profile's format, with every track in playlist order. Stage audio only when it is missing from the selected device at the intended export destination. Reuse audio already present or staged for that destination. With all audio present, the playlist file is the only item added. The preview distinguishes audio already on the device from audio queued for transfer.
- Syncthing assigns separate IDs to PC mirror and Android export shares. Relay live events keyed by registered Syncthing ID. An Android arrival enters Normal Sync through CQRS, preserves the current modal and playback, and ignores repeated or historical notifications. Resolve uncertain stream gaps by reconciling current peer state without treating historical messages as user navigation.

Before approval, verify the runtime dependency pins against package metadata, lock any remaining timing and retention constants, and bind the reviewed UI cases to the model's exact screen and branch references.
